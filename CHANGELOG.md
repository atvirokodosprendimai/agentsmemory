- **`am_kg_query` now returns only facts that are still true.** Previously a query named an entity and got back every fact ever recorded about it, retracted ones included, tagged `current:false` and left for the reader to honour — `current` appeared in every response and in no request. An agent that acted on a retracted fact was simply wrong, and nothing on the server prevented it. The new default is `status:"current"`, filtered server-side so what it removes never reaches the context window. **Nothing is hidden silently:** any response that filtered something carries `withheld: {"ended": N}` and a hint naming the parameter that restores it, because a session about to redo a rejected thing is precisely the session that does not know to ask for history. To restore the old behaviour per call, pass `status:"all"`; `status:"ended"` is the audit direction, for asking what the team has changed its mind about. Measured on the live graph at 1,363 triples the immediate saving is small — 47 expired facts, 3.4% — and this ADR does not rest on it; it rests on the default being correct, and on a ratio that only ever grows.

- **`am_search` returns the whole memory, not the matched chunk** (ADR-024, shipped earlier and still unannounced). Callers that assumed a chunk-sized payload now receive up to a whole memory — measured at 9,056 runes where a chunk was 1,600. `snippet_chars` bounds it; `snippet_chars: 0` asks for the whole memory explicitly.

- ⚠ **Three hook environment variables were REMOVED, not deprecated** (#46): `AGENTSMEMORY_SESSION_REPORT`, `AGENTSMEMORY_STATS_URL` and `AGENTSMEMORY_STATS_BASE`. Also changed, and worth knowing before it surprises you:

- **`am_update_drawer` refuses content over 4,000 runes** (#39, #40). `Update` re-embeds its whole content as ONE vector and never re-chunks, so a memory created small and grown in place was the one input that could exceed the embedder's window — and the TEI client asks for truncation, which means the server answered 200 with a vector for the *prefix*. The tail stayed stored, still came back from `am_get_drawer`, and was simply unfindable. Silent, and only on that path. The bound is deliberately conservative headroom rather than a measured ceiling for bge-m3 (which holds far more): it is sized so that pointing `EMBED_BACKEND` or `OLLAMA_EMBED_MODEL` at a smaller model stays survivable. It does not make every model safe — a 512-token model such as `mxbai-embed-large` tops out around 2k characters and 4,000 would still cut it. 1. **Check your hook environment for the three retired variables above.** This is the only change that goes silent rather than loud — nothing reads them, so nothing complains.
2. **If an integration depends on `am_kg_query` returning retracted facts, pin `status:"all"` at the call site.** Responses that filtered something say so via `withheld` and a hint, so this one announces itself.

- ⚠ **The cross-encoder's scores are now scaled by a sigmoid where the shipped code used min-max** (#57, ADR-030). `--rerank-norm` / `RERANK_NORM` is new and defaults to `sigmoid`; `minmax` is what you have been running and `rank` (position only) is the third option. This reorders any page a reranker touches, which makes it the one line in this release that alters an existing palace's results with nobody asking. **The reason it could not be left alone is a structural cancellation, not a tuning preference:** min-max is scale-free, so on a small pool at `RERANK_WEIGHT=0.5` both normalised terms become mirror images, the blend ties, and `sort.SliceStable` preserves the fused order — the cross-encoder was handed −5.0 against +5.0 and its verdict was **discarded**, and 0.5 is the single weight at which that happens (0.6 and 0.9 both behave). The same root cause let a `ONETIME` contribution grant a recurring plan permanently.

A `--socket` install produced hooks that could not contact anything and said nothing about it; a loopback server needs no token, and a repoint has to be reported rather than performed silently; and the recall hook was searching one room, which was not the room the answer is in.

- **Four gates that were weaker than their names, and one instrument that could not measure its own subject** (#87, #88, #89, #91). ## v0.0.105 — 2026-09-01

Everything merged since v0.0.104 (`6e26b88`, 2026-08-31): PR #147 — one merge, eleven commits, no migration. ⚠ **v0.0.101 through v0.0.104 were tagged without a section here and this release does not backfill them**; read their tag annotations and `git log` for what they shipped, and treat this file as complete only up to v0.0.100 and from v0.0.105 onward.

- **A memory moves as a memory, not as one of its rows** (#147, ADR-045). `am_update_drawer` refused to relocate anything over one chunk, on the sound reasoning that moving a single chunk would split a memory across two scopes and leave no search that returns all of it — but the remedy shipped was refusing the move rather than moving every chunk. `moveMemory` now patches all N rows in one transaction. The property the design rests on is that **ids are stable**: a move changes no content, so chunk boundaries and `chunk_index` are unchanged and `DrawerID` is never recomputed, which means every knowledge-graph fact, `code_anchors` row and pinned tunnel goes on naming a live row. That is exactly what the obvious alternative would have destroyed — `DrawerID` hashes wing, room, source, chunk index *and* content, so delete-and-refile mints N new ids and silently orphans everything pointing at the old ones, with nothing to repoint them. The transaction is not decoration either: `content_key` hashes wing and room, so relocating an N-chunk memory recomputes N keys against a partial unique index and **any one of them can collide** with a memory already at the destination; the test that pins this constructs a fixture colliding on chunk 1 and *not* chunk 0, because a fixture where every chunk collides fails on the first row and has nothing to roll back, so it could not exercise the branch that matters. The move also gained the half it never had in either direction: `Add`, `Supersede`, `Delete` and `InvalidateDrawer` all maintain derived edges and the move maintained none, so a relocated memory stayed reachable from the room it had **left** — a defect that predates this PR, since single-chunk moves were always allowed and always orphaned that edge — and `EnsureWingRoot` minted `<wing>.root` when a record landed in the entry room while nothing ended it when the last one left, which produces not a missing answer but a confident empty one: the root resolves `matched` and the hop a session makes next returns zero edges, the exact state `BackfillWingRoots` refuses to create on the boot path, arriving through the move path instead.

- **The entry record is served whole, and the limit that hid the bug is deleted rather than defended** (#147, ADR-046). Measured 2026-09-01 on a 3,600-rune entry record: `am_bootstrap` carried 1,600 runes, cut mid-sentence, and reported `truncation.omitted: 0` with an empty reason. **A front door that serves 44% of the entry protocol and says nothing was withheld is worse than one that fails, because the session proceeds.** The cause was structural — `DrawersByIDs` returns the root row, and a record over `ChunkSize` is several rows sharing a parent — so bootstrap now resolves them with `MemoryChunksByRoots`, one query for the whole eager tier rather than N on the one call no session skips, and reassembles with `reassembleMemory`, the same function the search path uses rather than a second answer to one question. With the serving fixed, `prepareWrite`'s refusal of a chunking record in `llm_init` had nothing left to protect: its own error message named that serving bug as its reason, and ADR-045 had already turned it into a two-call bypass, since the guard lives in `prepareWrite` while `moveMemory` patches rows directly — **a rule enforced on one path and open on another is worse than no rule, because it reads as a guarantee.** The cost is stated rather than hidden: `bootstrapEagerLimit` bounds how *many* records are inlined and nothing bounds how *large* each is, so a long entry record is now paid for by every session; byte-bounding the eager tier is filed in `BACKLOG.md` with a trigger and a note that the shape to reach for is a budget plus an honest truncation report, **not** a write-time refusal under a new name.

The reason to stay under one chunk is now stated as what it is — **recall, because one drawer is one vector** — rather than as a refusal that is gone.

The contract listed it under "optional" in every surface that states it — the served playbook, the `/am` command, both stop-hook checkpoints, the installed protocol, the web copy, and the tool's own MCP description. The reason it is a gate rather than a nicety was already team doctrine and needed only to be said where the contract is stated: **a drawer with no edge is an orphan** — reachable by search, invisible to traversal, and it still surfaces in the *author's* own search, which is exactly why authors believe it is reachable. Now: `aiagentmemory mcp search --digest <chars>` renders three lines per hit (identity; wing/room/date/STALE; the first region not already in the identity), one line per fact, and a trailing `N more hit(s) withheld` line — hits whole or withheld, never cut. `install --wing` writes `AGENTSMEMORY_WING` beside the URL in every hook prefix; with it set, each recall hook searches the project wing and then `wing_craft` under one 1,600-character budget, because `am_search` reads one wing per call and the protocol says every project reads craft — a single scoped call would have silenced 487 craft memories and nothing would have said so. A recall that could not run says `could not look` to the model through `additionalContext` as well as on stderr. Re-measured on the same prompt: **630 bytes (~157 tokens)**, project-only.

- **codebase-memory is a checked peer of the kit** (ADR-057; #265–#267). `doctor` has a `codebase-memory` row — ok / absent / DUPLICATE / BROKEN — judged from the settings file and the one MCP registry the install's Claude actually reads (`~/.claude.json` for a global install, `<dir>/.claude.json` for a pinned one; a union across config dirs was built, measured to report DUPLICATE over two legitimate installs, and rejected). `install --recommended` registers the peer once, under upstream's name `codebase-memory-mcp`, and retires the kit's `codebasememory`; every install collapses exact-duplicate `(matcher, type, command)` hook entries and prints what it removed. Measured on the owner's machine: `cbm-session-reminder` registered four times on SessionStart, four injections per session start, and `doctor` said nothing.

- **Every hook registration carries a timeout** (#263). 75 seconds on the settings.json route and all ten plugin-manifest entries — strictly above the 60-second client `--timeout` the recall hooks inherit, so the inner call gives up before the harness kills the hook; a registration an older kit wrote without one is upgraded on the next install.

**What this release got wrong first, because the failures are the useful part.** ⚠ **A union of registries manufactured findings.** Built for ADR-057 T1 on a reviewer's blocker, it reported DUPLICATE over the live global registry plus an inert ghost file here, and over two separate installs on the reviewer's machine; the reviewer measured both and withdrew the blocker. ⚠ **The dedupe key ignored `matcher`**, so one guard script registered for `Bash` and `Edit|Write` would have lost a registration on every install; review reproduced it. ⚠ **The digest's content line reprinted the identity line** on this palace's diary memories, whose first region is their `SESSION:|PROJ:|TASK:` header. ⚠ **A project-scoped recall silently dropped `wing_craft`**; the finding crossed the accept and went into the record afterwards. ⚠ **The digest's own trailing line echoed a 280-character prompt** — the budget line spending the budget — caught in this session's own hook output minutes after T1 shipped. ⚠ **Two displaced doc comments and one unrun hygiene package** went red in CI where a local run of the touched package alone had been green: run the whole check before pushing. ⚠ **A name-matching gate without a left boundary** read a test file's name as a wing name because `wing_` occurred mid-token.

**Upgrading to this release:** no migration, no re-embed, no re-index. Rebuild or reinstall the kit — `aiagentmemory install --wing <your wing>` is what puts `AGENTSMEMORY_WING` into the hook prefix; without it the hooks search the whole workspace as before and say so. `doctor` prints one more row and exits non-zero on a duplicated peer. The plugin manifest is bumped to match, as the version gate requires.

**What is NOT fixed.** A session that compacts loses its wake-up and nothing hands it back (backlog, from the same finding as ADR-058). Upstream codebase-memory's installer still appends a hook registration on every run; the kit corrects it on the next install rather than upstream not doing it. ADR-054's re-measurement waits for 2026-09-07. ADR-001 obligations, #234 and #246 wait on the owner.

## v0.0.120 — 2026-09-05

- **A compaction hands back the state it discarded** (ADR-059; #274). A `PreCompact` hook writes a `key=value` note — branch, HEAD, uncommitted count, the files this session edited, the task in flight — in the last moment before the summary exists, and the `SessionStart` recall opens the new context with it. `PreCompact` was chosen for the write and `SessionStart` for the read because only the second injects stdout, which is ADR-041's shipped defect stated as a design. When the note's branch is the current branch, the second 400-character call asks the wing's `llm_open_threads` checkpoint instead of `wing_craft`: measured on this palace, the fixed sentence under the hooks' 0.42 floor returned **zero** checkpoints (the three sat at 0.428–0.463, because every record in that room opens with the same words), while the sentence plus the branch name with no floor put the session's own checkpoint first.

- **The wake-up hands back the last turn** (ADR-061; #278, #279). The `Stop` hook writes the same shape of note per project at every turn end, including the last user prompts read from the transcript, and a `startup` or `resume` opens with it. `Stop` rather than `SessionEnd` because `SessionEnd` is not registered on Windows and never fires on a crash. Prompt text is verbatim on local disk in a 0700 directory as a 0600 file, both modes set explicitly and asserted; `AGENTSMEMORY_LAST_TURN_PROMPTS=0` keeps the note without prompts and `AGENTSMEMORY_LAST_TURN=off` writes nothing.

- **The compacted session is woken, not only instructed** (ADR-062; #280, #283, #285–#287, #290). The injection ends with a `PAUSE` naming `/amm <the task>`, a new Agent Skill carrying the grounding pipeline; the hook leaves a marker whose appearance a persistent monitor turns into a notification, because **no hook can invoke a skill but a notification does make a session take a turn** — a claim the record first asserted the other way, without a probe, and now carries its own refutation beside it.

- **A recall you can afford to page** (ADR-060; #277 — the one server change). `am_search` takes `ids_only`, returning per hit only the identity and the numbers a caller ranks and fetches by. Measured: 12,713–14,912 bytes per five-hit page against ~1,450–1,555 thin, a 9–10x cut, with `am_get_drawer` as the second layer. Borrowed from claude-mem's id-first disclosure, named in a competitor-parity note (#276) that also gated git-history minting behind a measurement — 7 of 20 real recall queries, all answered by commit or PR **bodies**, none by a subject or a diff.

- **`doctor` checks wiring for every installed hook** (#291), not only the three that declare `stdout-injected`. Six of nine shipped hooks were outside its universe, including the note writer whose absence nobody could explain. The channel decides whether a hook can speak; it must not decide whether a hook is wired.

- **ADR-049's three rebind tests, restored** (#282). They existed and were deleted by an unrelated commit that rewrote the file without saying so; the loopback guard served untested for a week while the task's fence stayed green, because `go test -run` over a pattern matching nothing exits 0. `TestEveryTaskTableTestExists` now resolves every evidenced task's test rows with `go/parser`, and logs its live figures on a `-v` run rather than freezing them here. Found by a peer pointing its own gates at this corpus.

**What this release got wrong first, because the failures are the useful part.** Every one was invisible to a green suite, and every one was found by running the deployed artifact against a real transcript or a real directory rather than a fixture. ⚠ **The wake fired once per session and was then silently dead**: its seen-list keyed on the marker path, which is the constant session id, so the first compaction pinned it for ever — degrading exactly as a session gets longer. ⚠ **The fix for that deleted other sessions' markers**, where the code it replaced merely ignored them; one monitor woke for a compaction that never happened and the session that did compact never woke, because the marker directory is shared by every session on the machine. ⚠ **The note was written and binned a millisecond later**: a `{ }` group takes its exit status from its last command, and `[ -n "$PENDING" ] && printf …` is false whenever every user turn is harness chrome, so the `||` arm removed the note while the hook exited 0 and the harness printed "completed successfully". ⚠ **Seven kinds of harness chrome** were labelled as the task in flight before the list was complete — `/compact` itself, a wrapped slash command, a task notification, a system reminder, the post-compaction preamble, a relayed peer message, and the kit's own Stop-hook feedback — three of them found only because a second session's transcript held shapes the first's did not. ⚠ **A prefix was tidied into a member name**: `^<local-command` became `^<local-command-stdout`, which reads as precision and silently let `<local-command-caveat>` through. ⚠ **A performance claim was merged with a wrong explanation** and corrected in a follow-up (#289): the speedup is real but engine-dependent — 47.25s→0.10s under GNU sed, 1.88s→0.12s under BSD, with the synthetic shapes ranking in opposite orders — and the timeout story it implied was refuted by the reporter's own measurement. ⚠ **A constant became a third copy of a string** pinned by nothing; ## v0.0.121 — 2026-09-06

Everything merged since v0.0.120 (`d87bc05`, the previous day): PRs #293–#310, closing #205, #249, #296, #305 and #306. One sentence: **recall stopped losing prompts, stopped answering from the wrong project, and stopped charging every session for nineteen other projects' room lists.** No server migration, no re-embed; one server change (`am_status` payload) and the rest in the Claude Code kit and the repository's own gates.

- **A prompt containing `=` silently lost its recall entirely** (#310). `ParseArgs` treated any bare tail token containing an equals sign as a `key=value` argument, and both shipped hooks pass their query as a bare positional — so the query vanished into the argument map, the server answered `required argument "query" not found`, and the session was told only `agentsmemory could not look`. Reported by a peer as intermittent, "roughly half" its prompts; deterministic once the query is the variable rather than the load. A second peer then found the half nobody could see from inside one session: the cross-session message wrapper carries `from="…"` and `from-name="…"`, so **every message from every peer lost its recall, whatever it said**, including the one reporting the bug. A bare token is now an argument only when the tool's own schema declares the key **and** the token holds no whitespace.

- **The recall hook follows the project, not the install** (#308, closing #305). The installer baked `AGENTSMEMORY_WING` onto the hook's command line, where a leading assignment beats the inherited environment, and hook registrations land in the user-level `settings.json` whatever `--scope` says — so one project's wing was recalled in every project on the machine. Observed, not theorised: a session in another repository was handed this project's diary and `llm_open_threads` checkpoint. The hook now reads `.aiagentmemory.local` then `.aiagentmemory` from the project directory, and falls back to the baked value, which is what most installs still rely on.

- **`am_status` no longer serves every session nineteen other projects' room lists** (#309, closing #306). Measured on this palace: 11,995 bytes, 10,145 of them the wings array, on the one call the wake-up protocol makes first in every session in every project. Other wings keep their name and counts — the identity check start-here tells sessions to make — and lose only the room breakdown, which `am_get_taxonomy` still serves whole. A registration with no resolvable wing keeps today's payload, because inventing one is the silent-wrong-answer failure #305 records the cost of.

- **`--team` asserts an identity that exists** (#302, closing #249). It recorded no `search_events` row on a fresh database — the trusted-local identity has no `teams` row, so the insert failed a foreign key silently and the flag looked like it worked.
